# 第一阶段：第一人称移动控制器（Unity）

目标：做出接近端游手感的移动，重点是 **Shift 静步** 和 **急停**（松开方向键，或按反方向键）。

## 打开项目

需要 **Unity 6**。推荐安装 6000.0 LTS 的最新补丁版本（不低于 6000.0.58f2，更早的补丁版本有已公开的安全漏洞 CVE-2025-59489）。

1. 打开 Unity Hub → **Add** → **Add project from disk** → 选择仓库里的 `unity` 文件夹。
2. 如果 Hub 提示没有安装 6000.0.58f2，可以选择你已经安装的、版本号更新的 Unity 6 打开（会提示升级项目，点继续）。不要用更旧的版本打开。
3. 第一次打开会自动安装 Input System 包。如果弹出 “enable the new input backends” 之类的对话框，点 **Yes**，编辑器会重启。
   - 没有弹窗但运行时角色不动：打开 **Edit → Project Settings → Player → Other Settings → Active Input Handling**，改成 **Input System Package (New)** 或 **Both**。
4. 菜单栏点 **AimTrainer → 创建移动测试场景（第一阶段）**，会生成并打开 `Assets/AimTrainer/Scenes/MovementTest.unity`。
5. 点 **Play**，再点一下 Game 视图锁定鼠标，就可以开始走了。按 **Esc** 释放鼠标。

第一次打开并生成场景后，`unity/` 下会多出 `ProjectSettings/` 里的设置文件、`Packages/packages-lock.json`、`Assets/AimTrainer/Scenes`、`Settings` 和 `Generated` 等文件，可以一起提交。`.meta` 文件必须和对应的文件一起提交，否则场景里的脚本引用会丢失。`Library/`、`Temp/`、`Logs/`、`UserSettings/` 已经在 `.gitignore` 里忽略了。

**如果打开项目时报包错误**（比如某个包版本找不到）：在 Unity Hub 里用 **Universal 3D** 或 **3D (Built-In Render Pipeline)** 模板新建一个 Unity 6 项目，把仓库里的 `unity/Assets/AimTrainer` 整个文件夹复制到新项目的 `Assets` 下，再按第 3、4 步操作。

## 按键

| 按键 | 作用 |
|------|------|
| W A S D | 移动 |
| 左 Shift（按住） | 静步 |
| 左 Ctrl 或 C（按住） | 下蹲 |
| 空格 / 鼠标滚轮 | 跳跃 |
| 鼠标左键 | 锁定鼠标（第二阶段改为射击） |
| Esc | 释放鼠标 |
| F1 | 显示 / 隐藏调试面板 |
| F2 | 累计转角归零 |

在编辑器里按 Ctrl 加其他键时，偶尔会触发编辑器自己的快捷键；打包成独立程序后没有这个问题。

## 测试场景

出生点在场地南侧，面朝北。走进每个区域时，左上角面板会显示这个区域怎么测。

| 区域 | 位置 | 测什么 |
|------|------|--------|
| 速度跑道 | 左侧 | 每 5 米一条橙线。全速跑一格约 0.93 秒，静步约 1.8 秒 |
| 台阶测试 | 左中偏南 | 0.20 / 0.35 / 0.55 / 0.70 米高的台子，0.40 米以下能直接走上去；走下台子时不会短暂“腾空” |
| 跳跃测试 | 左中偏北 | 0.70 / 0.85 / 1.10 / 1.25 米高的台子，前两个能跳上去 |
| 下蹲通道 | 中间 | 顶高 1.45 米，必须蹲着通过，在里面松开下蹲不会站起来 |
| 急停靶场 | 右侧 | 9 个红色靶子（头部中心 1.6 米），练 A/D 横跳急停 |

## 调试面板

左上角面板实时显示：

- **FPS 和帧时间**：括号里是最近 0.5 秒内最慢的一帧。
- **水平速度和状态**：静止 / 跑步 / 静步 / 下蹲 / 空中。
- **精准射击**：站在地面且水平速度 ≤ 1.6 米/秒时显示“可以”。速度条和速度曲线变绿也是这个意思（在空中时一律不算）。
- **松键急停 / 反向急停**：从全速跑动开始急停，到速度降到 1.6 米/秒以下的实测耗时，旁边是按当前参数算出的理论值。只有急停前速度达到跑步速度的 95% 才会测量，所以静步时不会刷新。手指很难在同一帧松开 D、按下 A，中间没有输入的几帧会算进反向急停的耗时，并单独显示为“含空档 X ms”。
- **灵敏度换算**：360° 需要多少鼠标计数、多少厘米（DPI 在 HUD 组件上设置，只影响显示）。
- **累计转角**：用来核对 360° 距离，见下文。
- **速度曲线**：最近 2 秒的水平速度，黄线是精准门槛。左右横跳时能直观看到每次急停花了多久。

## 实现原理

### 水平速度：指数靠拢，不用摩擦力

每帧让水平速度按指数规律向“目标速度”靠拢：

```
v ← 目标 + (v − 目标) · e^(−速率 · dt)
```

这个公式与帧率无关：同样经过 0.5 秒，30 帧和 500 帧算出的速度完全相同。单元测试在 30 / 60 / 144 / 240 / 500 帧下都检查了这一点。

目标速度和速率按情况选择：

| 情况 | 目标速度 | 速率 |
|------|---------|------|
| 有方向输入 | 输入方向 × 当前姿态速度 | `groundAcceleration` = 13 |
| 松开所有方向键 | 0 | `releaseDeceleration` = 18 |
| 按下与当前速度相反的方向 | 反方向 × 当前姿态速度 | `counterStrafeDeceleration` = 13 |
| 空中有输入 | 输入方向 × 当前姿态速度 | `airAcceleration` = 1.2（一次跳跃大约完成一半的变向） |
| 空中无输入 | 保持原速度 | — |

### 为什么反向急停比松键快

松键时目标是 0，速度从 5.4 衰减到 1.6 需要：

```
t = ln(5.4 / 1.6) / 18 ≈ 68 毫秒
```

按反方向键时目标是 −5.4，离当前速度更远，越过 1.6 的速度更快：

```
v(t) = −5.4 + (5.4 + 5.4) · e^(−13t)，令 v(t) = 1.6
t = ln(10.8 / 7.0) / 13 ≈ 33 毫秒
```

所以即使速率数值更小，反向急停也只要松键一半的时间。这就是端游里“按反方向键急停”的手感来源。

### 静步和下蹲

静步只是把目标速度乘以 0.52（5.4 → 2.8 米/秒），加速和减速规律不变。下蹲按下蹲程度在 1 和 0.42 之间插值，和静步同时按时取较慢的一个。下蹲在 0.1 秒内完成，身体高度从 1.8 米降到 1.3 米，眼睛高度从 1.6 米降到 1.15 米。想站起来时会先检查头顶空间，被挡住就保持蹲姿。

### 跳跃和重力

起跳速度由跳高和重力算出：`v₀ = √(2 × 20 × 0.9) = 6 米/秒`，滞空 0.6 秒。竖直方向用恒定重力的精确公式积分，跳高不随帧率变化。

另外两个细节：

- **跳跃缓冲 0.08 秒**：落地前一点点按下跳跃，落地瞬间会自动起跳。
- **空中不上台阶**：在地面上能直接走上 0.4 米高的台阶，但空中把这个值设为 0，否则跳到一半会被“吸”上本来跳不上的台子。

### 下台阶和下坡

CharacterController 本身不会自动“贴地”：走下台子或跑下陡坡时，脚下的地面比每帧向下的位移掉得更快，角色会短暂离地，状态在“空中”和地面之间闪烁，精准判定也会跟着闪。所以上一帧还在地面、这一帧却离地时，控制器会向下探测不超过一个台阶高度（0.4 米），找到能站的地面就直接贴上去。更高的落差仍然正常下落。

### 下蹲时的台阶高度

PhysX 在自动上台阶时会把胶囊临时抬高一个台阶高度。下蹲身高 1.3 米加上 0.4 米的台阶，比 1.45 米的矮通道还高，蹲着会卡在入口。所以下蹲时台阶高度按下蹲程度降到 `crouchStepOffset`（0.1 米）。如果以后加了更矮的通道，要保证 `crouchStepOffset` 小于“通道净高 − 下蹲身高 − 0.03”。

### 撞墙

撞到墙后，水平速度改成实际走出去的速度：贴墙斜着走会沿墙滑动，正面撞墙会停下，离开墙时不会突然冲出去。

### 鼠标视角

- 每个鼠标计数转 `0.07° × 灵敏度`，和端游相同，填游戏内的灵敏度数值即可。
- Unity 摄像机的视野是竖直方向的，脚本根据屏幕宽高比实时换算，保证水平视野固定为 103°。16:9 屏幕上对应竖直约 70.5°。
- 每帧先转视角再算移动，所以移动方向用的就是这一帧最新的朝向。

## 参数一览

移动参数都在 `Assets/AimTrainer/Settings/DefaultMovement.asset` 里（生成测试场景时自动创建）。选中它，在 Inspector 里修改；运行中修改立即生效，退出 Play 后也会保留。

| 参数 | 默认值 | 说明 |
|------|--------|------|
| runSpeed | 5.4 | 跑步速度（米/秒） |
| walkSpeedMultiplier | 0.52 | 静步系数 → 2.8 米/秒 |
| crouchSpeedMultiplier | 0.42 | 下蹲系数 → 2.3 米/秒 |
| groundAcceleration | 13 | 加速速率，约 177 毫秒达到 90% 速度 |
| releaseDeceleration | 18 | 松键减速速率 |
| counterStrafeDeceleration | 13 | 反向急停速率 |
| stopSnapSpeed | 0.05 | 松键后低于此速度直接归零 |
| airAcceleration | 1.2 | 空中转向速率 |
| gravity | 20 | 重力（米/秒²） |
| jumpHeight | 0.9 | 跳高（米） |
| jumpBufferTime | 0.08 | 跳跃缓冲（秒） |
| groundStickSpeed | 2 | 站在地面时的向下贴地速度（米/秒） |
| stepOffset | 0.4 | 能直接走上的台阶高度（米），也是下台阶贴地的最大距离 |
| crouchStepOffset | 0.1 | 完全蹲下时的台阶高度（米） |
| standingHeight / crouchHeight | 1.8 / 1.3 | 站立 / 下蹲身高（米） |
| standingEyeHeight / crouchEyeHeight | 1.6 / 1.15 | 站立 / 下蹲眼睛高度（米） |
| crouchTransitionTime | 0.1 | 下蹲耗时（秒） |
| accurateSpeedThreshold | 1.6 | 精准射击速度门槛（米/秒） |

除 `stepOffset` 外，这些数值都来自网页原型，是按手感调出来的，**不是官方数据**。原型里能直接走上 0.5 米的台阶，Unity 版改成了 0.4 米，这样台阶测试里 0.55 米的台子必须跳上去。

**灵敏度、水平视野、Invert Y、滚轮跳跃不在这个资源里**，它们在场景中 `Player` 物体的 **Player Controller** 组件上；显示用的鼠标 DPI 在同一物体的 **Movement Debug Hud** 组件上。改这些要先退出 Play，改完按 Ctrl+S 保存场景，否则退出 Play 时会丢失。重新生成测试场景会把它们恢复成默认值。

调参建议：

- 觉得急停“拖泥带水”：调大 `releaseDeceleration` 或 `counterStrafeDeceleration`。
- 觉得起步太肉：调大 `groundAcceleration`。
- 想让急停更依赖反向键：调小 `releaseDeceleration`，保持 `counterStrafeDeceleration` 不变。
- 觉得空中变向太灵活：把 `airAcceleration` 调到 0.3 左右（一次跳跃只完成约 16% 的变向）。

## 验收步骤

对应 `docs/ROADMAP.md` 第一阶段的四条验收标准：

1. **速度**：在速度跑道上全速跑，面板速度应稳定在 5.40；按住 Shift 应稳定在 2.81。
2. **松键急停**：全速跑动中松开 W，面板“松键急停”应约为 68 毫秒。
3. **反向急停**：在急停靶场按住 D 跑满速后，**松开 D 的同时按下 A**，“反向急停”应约为 33 毫秒加上空档时间。不要两个键一起按住：A 和 D 同时按住等于没有输入，只会算作松键急停。
4. **灵敏度**：先退出 Play，在 Hierarchy 里选中 `Player`，把 **Player Controller** 组件的 Sensitivity 改成游戏内灵敏度，把 **Movement Debug Hud** 组件的 Mouse Dpi 改成你的鼠标 DPI，按 Ctrl+S 保存场景。再进入 Play，按 F2 归零，在鼠标垫上标出面板显示的“360° 需要的厘米数”，拖过这段距离后“累计转角”应约为 360°。也可以和端游里实际转一圈的距离对比。

另外可以在 Unity 里运行单元测试：**Window → General → Test Runner → EditMode → Run All**，共 41 个测试，覆盖上面所有公式在不同帧率下的结果。

## 已知限制

- **鼠标原始输入**：Windows 上 Input System 的鼠标位移来自原始输入，不受“提高指针精确度”影响。macOS 上的位移可能带有系统加速，360° 距离会对不上。
- **编辑器里的帧率和延迟**比打包后的程序差。最终手感以打包出来的程序为准：**File → Build Profiles**（较早的 Unity 6 版本叫 Build Settings）→ 选 Windows → **Build And Run**。测试场景已经自动加入打包列表。
- 当前没有斜坡加速、落地减速、跳跃后的移动惩罚。如果和端游对比发现明显差异，告诉我具体情况再加。
